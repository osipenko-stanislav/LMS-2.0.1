# LMS 2.0.1 — Agent Rules

## Приоритеты

1. Визуальное качество и целостность интерфейса.
2. Переиспользование компонентов и композиций.
3. Разделение данных, бизнес-логики и представления.
4. Простота архитектуры и скорость изменений.

## Обязательные правила

- Используй существующие компоненты Linear UI как основу интерфейса.
- Роли Linear/DesignKit, Woblo, Woday и Beautiful UI определены в `DESIGN.md`; внешние AI-native паттерны адаптируй к существующей системе LMS.
- Страницы и Generative UI переиспользуют компоненты, контракты, данные и действия; композиция адаптируется к контексту использования.
- Не дублируй компоненты, стили и бизнес-операции.
- Новые функции реализуй через существующие контракты и слои.
- Контент и демонстрационные данные храни отдельно от компонентов.
- Фиксируй происхождение предметных данных в метаданных; технические подписи о демонстрационных данных не выводи в пользовательский интерфейс.
- Изменения состава и порядка блоков выполняй через конфигурацию, если существующий контракт это поддерживает.
- Не вводи новые зависимости и архитектурные абстракции без технической необходимости.
- Сохраняй работающие сценарии и существующие публичные контракты, если задача явно не требует их изменения.
- Не меняй архитектурные и дизайн-правила без согласования.

## Работа над задачами

- Перед изменениями найди существующую реализацию и её зависимости.
- Вноси минимальные изменения, достаточные для выполнения задачи.
- Выбирай проверки соразмерно изменениям: для кода — затронутые сценарии, типизация и сборка; для документации — согласованность текста без запуска сборки и тестов.
- Для визуальных изменений проверяй реальный рендер.
- Не утверждай, что проверка выполнена, если она не запускалась.
- В конце кратко сообщай результат, ограничения и проведённые проверки.

Подробности архитектуры — `ARCHITECTURE.md`. Визуальные правила — `DESIGN.md`.
